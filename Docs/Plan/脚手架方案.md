# 《晴天》VFX Graph 脚手架方案与新手指南

版本：方案 1.2｜2026-11-16｜独立 QingTianVFX 与 M1 已授权；真实完成状态以 DEVELOPMENT.md 为准。

最终目标是：在Windows Unity编辑器按Play后，同一首269.747秒的《晴天》从头播放到尾；同一套VFX Graph粒子持续运动，章节慢变、歌词聚散、节拍/音量微扰同时存在，在四个固定时刻经过风格帧状态。当前已授权的第一里程碑严格限定为：**还没有粒子，按下播放，参数已经随音乐变化；精确锚点的最终视觉参数逐项等于预设。** 纯黑背景、暗幕方案、30 fps已确定；iPhone（Metal/ARKit）、AR与手套后置。

本方案依赖 [技术报告](技术报告.md) 的平台边界和 [风格帧拆解](风格帧拆解.md) 的测量/预设。名字与数值按下文合同统一；不是要求新手第一天就接完所有参数。

**工程起点已确定：`D:/Works/智能交互设计/QingTianVFX`，从编辑器自带URP官方模板独立创建。** [DEVELOPMENT.md](../../DEVELOPMENT.md)是唯一开发上下文与最高工程文档；其他工程的历史、配置和代码均不作为本工程基线。当前指令优先，方案与DEVELOPMENT.md冲突时以后者为准。

## 2. 数据与时钟规则

### 2.1 必须先解决的输入

| 输入 | 当前情况 | 适配规则 |
|---|---|---|
| 原音源 | SHA与timeline一致，96 kHz双声道FLAC清单；官方6.3文档支持FLAC | 验证直接导入，有具体问题才转换WAV；允许重采样但不得裁掉开头；核验长度/起点；原曲与派生含曲音频不进公开仓库 |
| timeline.json | 4 章首尾连续；50 句，21 句需听审 | 区间采用 `[start,end)`，歌曲末端单独钳制；验证句子属于章、时间非负、有序且不超时长 |
| 歌词“成形程度” | 是句级意象标签，不是花瓣开关 | 另存 `visual_score` 映射：哪一句主要驱动天气/M2 两光/M3 花；C2/C4 的成形句也可只让雨线/光群暂时聚合 |
| dispersal_events | 有句间空档，部分可能含尾音 | 句末做平滑释放，不在 end 时间突然清空；按听审修正尾音 |
| 节拍 | 层级已确定68 BPM；源timeline只给候选说明，既有MIR约136 BPM时间列可用 | 从136 BPM的beat序列隔拍采样，比较奇/偶两相位并记录局部声学依据；导出68 BPM数据与本地核对音频；不把0秒或选中相位直接称作小节第一拍 |
| 音频特征缓存 | 既有 MIR 有 features_full.npz、0.5 s CSV | 0.5 s CSV 不足以做快脉冲；需要快层时读取高分辨率数据/时间戳或实时计算；不直接拿旧参考视频的缓存 |

预定 `SongTime = dspTime − scheduledStart + seekOffset`，暂停期间保持逻辑时间；恢复时重建偏移。不要累加每帧 deltaTime 当整曲主时钟；应用切后台、设备音频配置变化都要处理并验证。播放时音频音高固定为 1，结束不默认循环。

`GetSpectrumData` 使用已分配数组，初值建议 FFT 1024/2048 两档择一；按实际输出采样率积分 low=约 30–250 Hz、high=约 2–10 kHz（上限不超过 Nyquist），不是按原 FLAC 的 96 kHz 硬算。RMS 从输出样本估计。按同曲统计参考进行 0–1 归一化并限幅；attack≈30 ms/release≈180 ms、Beat 衰减≈120 ms 是设计初值。显示“未准备好”，不要把初始空频谱解释为歌曲没有声音。[Unity 频谱 API](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/AudioSource.GetSpectrumData.html)、[DSP 时钟](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/AudioSettings-dspTime.html)

### 2.2 连续参数的合成

1. 根据SongTime求章节基态与辅助曲线，在56.80/93.61/155.41/264.05秒精确经过四个完整预设；所有已有参数名与四组值不变。
2. 句内用平滑“起—聚—释”包络形成相对基态的偏移：起始约20%进入、中央约45%保持可辨、余下释放；短句/尾音另校准。FlowerForm不在预设0.85上无条件再加包络；将句级散态/峰值目标折算为偏移，C2/C4按意象保留残弧。
3. 快层只给小偏移，例如FiberWidth约±8%，Light/Dust约±15%；中心主要由慢层控制。原始RMS、频段、Beat和句包络单列，持续按真实输入求值。
4. 对中/快层偏移乘统一的平滑锚点权重：远离锚点为1，靠近时平滑减小，精确锚点为0，离开后平滑恢复。权重窗口与连续性记录在实现证据；不是在单帧强制跳值。预设自身NoiseAmp/FlowSpeed保留，不能把所有动态项清零。
5. 基态加受约束偏移后统一限幅，输出最终参数包；合法的四预设必须通过限幅而不被改写。M1精确锚点应逐字段等于该帧预设，不能只测基态；同时检查前后采样连续。M1不写Graph，M2后再接参数桥。

“精确锚点”通过求值器直接接收该秒数进行检查，而非等待30 fps帧恰好命中。浮点误差采用实现中明示的微小容差；颜色在相同表示空间核对。`SongTime`、`FlowPhase`、原始音频/句信号不是四帧预设字段，不应被覆盖。M1调试UI必须同时显示原始信号、最终视觉值、锚点误差和调制权重，便于判断音频仍持续而偏移已平滑归零。

颜色在 Linear 空间插值，preset 的 hex 是 sRGB 输入。长度/中心在统一坐标系插值；角度取连续短路径。`TargetCount` 是浮点可见目标，按稳定 ID 的连续权重改变密度，**不是每帧改 Initialize Capacity**。活粒子数与可见数分别统计；不能以透明隐藏声称已经省掉模拟。

FlowSpeed 先只由慢层求值；FlowPhase 是对速度积分得到的累计相位，不用 `SongTime × 当前速度`，否则调速会跳相。初版快层通过噪声幅度和位置微扰表现能量；确需实时加速再增加音频速度积分，并处理 seek 历史。不要为了少几个节点牺牲连续性。

### 2.3 图内执行边界

VFX 结构负责 Spawn、Initialize、Update、Output；复杂目标函数放外部 HLSL。花层先使用可求值的目标混合，不上真实流体/复杂弹簧求解。解析目标控制 position 时，要避免 Update 的默认速度积分再推一次导致双重运动；具体关闭/覆盖选项按图配置核对。

条带先从稳定的一次性多条带样例学索引，目标为同一 strip 内保持次序；C1–C4 只改变曲线与可见权重。寿命要覆盖全曲加准备余量，循环边界若存在则在低 alpha 区平滑；章切换不得 Reinit。重播会统一重置；seek 使用确定性参数求值，并对仍有历史状态的层执行固定步长预演。跨 GPU 的逐像素确定性不作为承诺。[组件 API](https://docs.unity.cn/Packages/com.unity.visualeffectgraph@17.3/manual/ComponentAPI.html)、[HLSL Block](https://docs.unity.cn/Packages/com.unity.visualeffectgraph@17.3/manual/Block-CustomHLSL.html)

## 3. 参数合同 v1

### 3.1 坐标、单位与先接的参数

测量统一为左上角 `(0,0)`、右下角 `(1,1)`；x 按画宽、y 按画高归一化。长度后缀未写 UV 的 `Size/Width/Radius` 默认以**画宽 W**为单位，避免画面宽高比扭曲；例如 0.001W 在原图等于 1.672 像素。VFX local 坐标需由桥统一转换，y 反向，且补偿 aspect。初版固定约 16:9 横屏、相机固定；不要直接把图片 UV 当成 Unity 世界米。

参考空间提案：宽 10 Unity units、高 10/aspect；深度使用无量纲 0–1（0 近、1 远）映射到相机前的浅层空间，**不是从图片恢复出的米制深度**。AR 后另设世界尺度与锚点，切换相机后要重新验收构图。

M1必须求值并导出下表完整视觉合同，面板优先显示：`SongTime`、`Rms01`、`BeatPulse`、`LyricEnvelope`、`LightCenterA/B`、`LightGainA/B`、`FlowerForm`、`GapWidth`、`FiberWidth`、`MasterGain`。M2搭图才按视觉层逐次接线。Blackboard使用下述大小写；向量保持类型，避免意义不明的Float0。`LayerDepth/LayerDepthJitter`是可选分层配置，依文档三另表保存。

### 3.2 公共信号（输入，不是从静态图片估出的预设）

| 名字 / 类型 | 范围 / 单位 | 来源、用途 |
|---|---|---|
| SongTime / Float | 0–269.747208 s | DSP 逻辑歌曲时间；所有层 |
| FlowPhase / Float | 累积非负 cycles | 对 FlowSpeed 积分并按路径尺度换算；丝带/星尘/雾共用 |
| ChapterBlend / Vector4 | 每分量 0–1，和=1 | 慢层权重；四态/调试使用，复杂形态参数仍集中由桥求值 |
| LyricEnvelope / Float | 0–1 | 句包络；驱动当前指定意象的聚散，不无条件施加到所有层 |
| Rms01、Low01、High01 / Float | 各 0–1 | 实时音量/频段；只负责有限局部调制 |
| BeatPulse、Onset01 / Float | 各 0–1 | 校准 beat 衰减包络 / 瞬态估计；不能混作拍号 |
| MasterGain / Float | 0–1 | 全局淡入淡出和调试；开头约 0–8 s 渐入，结尾 265.54–269.747 s 渐出 |

| 黑隙 | GapCenter / Vector2 | 0–1 UV | 两光连线剖面上暗隙中心；慢 |
| 黑隙 | GapWidth / Float | 0–0.35 W | 剖面宽度；慢，**不受beat缩到零** |
| 黑隙 | GapNormalAngle / Float | -180–180° | 人工估计的局部黑隙法线屏幕角；不是两光连线的测量角 |
| 黑隙 | GapLength / Float | 0.05–1.20 W | 局部排斥区沿切线长度；是造型提案，不是图像测值 |
| 黑隙 | GapStrength / Float | 0–1 | 0不施加，1保护；C1=0，C2/C3/C4=1。雨层可用0.35倍强度 |
| 虚实 | FocusDepth / Float | 0–1 | 归一化清晰层位置，初值0.50；人工视觉代理 |
| 虚实 | DepthSpread / Float | 0–1 | 深度分散，慢；不表示真实景深距离 |
| 虚实 | SoftFraction / Float | 0–1 | 星尘/雾混合中倾向柔化的比例；与测量图块比例不同 |
| 每层深度项 | LayerDepth、LayerDepthJitter / Float | 中心0–1，扰动0–0.20 | 见文档三深度表；各章内固定。花在章间先散开，再切到新深度；不随每拍拉焦 |
| 后处理 | BloomIntensity / Float | 0–1.5（初版限幅） | 受控辉光；写 URP Volume，**不是 VFX Blackboard**；慢，不每拍开关 |

FlowA/B 四点是拟合曲线的最少几何资料。首次图形实现若这两条曲线不足以还原 C3 翻卷，应先局部增加控制段，再考虑更多参数；不会以参数表“字段齐全”代替实际形态验收。黑隙不是无限长直线剪刀：只作用于局部有界区域，外缘跟主流场变形，留出自然过渡。GapWidth 沿两光连线测得，而 GapNormalAngle 是人工方向提案；局部直带近似时，法向宽度取剖面宽度乘以“剖面方向与法线夹角余弦的绝对值”，避免把斜切长度当最短宽度。曲边最终仍需以实际输出重新测量。

### 3.4 防止参数互相打架

每个属性只有参数桥一个写入者。HLSL 读到的 `LightGain/FiberWidth/FlowerForm` 等已是最终值，就不要在图里再乘一次 Rms01；公共原始信号只用于专门的粒子局部相位/亮点权重。每张图声明实际需要的属性清单，缺名称/类型时 DebugPanel 显示完整路径，不能默默忽略。

Blackboard 不是自动合同：新增一个 Float 后仍需接到实际 block/output，面板有数字跳动不意味着图已响应。第二阶段先用单个 Quad 对不同参数作肉眼可见的变化，证明桥与节点真正连通。

每一份正式搭建步骤会按“要看到的效果→需要的Blackboard属性→节点/Block所在Context→每根线的源口与目标口→Inspector值→常见错误→截图验收”写，不让新手只凭总览猜连线。本轮实现M1基础；此大纲用于M2以后，当前不搭粒子图。

### 学习中最容易混淆的点

- Capacity 是容量；SpawnRate 是每秒发射；TargetCount 是本方案的可见预算，三者不是同一个值。
- 在 Initialize 写入的属性不会自动跟着每帧参数变化；需要持续变化的大小、目标位置或颜色，要在 Update/Output 合适位置接最终属性。
- Output 的 Additive 是叠光，不能画出黑色；Soft Particle 处理交界软边，不能代替景深。
- 图里采样花/曲线目标仍是真实 VFX 粒子；直接贴整张参考图到Quad不是本任务的还原。
- bounds 要覆盖完整动态范围；GPU裁剪造成的“突然不见”不能靠一直增大粒子数解决。
- 可见数量降到0仍可能占GPU模拟资源；手机低档容量与演出中的密度变化分开设置。
