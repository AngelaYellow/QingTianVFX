## 明天怎么演示

1. 双击 **启动演示.cmd**，等“本地音频已就绪”，点击“播放整首晴天”。不要直接双击 HTML。

5. 演示失败时直接打开 **LocalOnly/晴天_整曲备份.mp4**。需要比较改动，打开 [验收页面](http://127.0.0.1:47841/review.html)。

## 实际实现

**位置、速度、寿命在 GPU 上计算，JS 不逐个更新粒子。** `512 × 512 = 262,144` 个有状态的材料载体使用双缓冲浮点纹理。GPU 每秒约 30 次积分，每个显示帧用当前速度预测期间位置；音乐时钟按秒推进，不按渲染帧数推进。

重建细节与运动求解分开：四个精确锚点使用 **1,573,352 个采样点**覆盖原图每个像素。离开锚点时，雾样本逐渐减少、覆盖范围相应增大；细丝保留更密集的采样，随附近 GPU 载体运输。它们都是 shader 输出的粒子样本；“157 万采样点”不等于“157 万独立求解的状态”，也不等于屏幕可见亮点数。该预算不适用于未来安卓 VFX Graph。

主体的推进由两条合同贝塞尔方向引导；粉雾、青雾分别绕自己的光心运动，叠加在当前位置求值的连续旋涡场。雾拥有交错的年龄、补入与消散；细丝采用更连贯的材料年龄，保留成束纹理。雾与细丝分别累积，雾单独柔化合成。深度代理影响速度、尺寸与轻微视差，属于 **2.5D**，没有恢复真实三维烟体，也不是 Navier–Stokes 流体求解。

图片参与颜色采样和目标位置，不是背景图片或整屏扭曲后处理。四帧按已知的两光与花中心分区，以等质量空间划分建立对应，再生成平滑运输坐标。分区是启发式，不冒充精确语义分割。章节间，同一份材料的位置向下一个目标移动，颜色随材料插值；不是四张全屏图层交叉淡化。

## 音乐怎样推动形体

| 尺度 / 信号 | 实际作用 |
|---|---|
| 四章、四个锚点 | 同一组材料的目标坐标连续迁移；两光关系、花位置、黑隙和颜色逐步变化 |
| 主歌 / 副歌 | 曲式等级改变输运速度和旋涡强度；主歌 1 为 0.56、副歌 1 为 1.35、副歌 2 为 1.55；边界 2.4 秒平滑过渡 |
| 歌词句包络 | `FlowerForm` 改变花区域向形状聚拢的约束；`FlowerBreak` 改变释放后的流散 |
| 实时低频、RMS | 主体推进速度、波前强度、柔光亮度；低频不直接搬动慢层光心 |
| 实时高频 | 细尺度卷曲场的幅度 |
| 实时 onset | 触发独立传播波前；先推开、再释放，有惯性，不把整张画面同步放大 |
| `beats68` 节拍 × 实时低频/RMS | 产生有空间传播的重拍冲击；与 onset 共存，最多保留六个活动事件 |
| `RainSpeed`、低频 | 对雨的路程积分，变速不会因 `time × speed` 重新定位而倒跳 |

曲式、句时刻和节拍骨架来自既有数据；声学频段与 onset 来自实际 Web Audio 输入。没有宣称在线识别 BPM 或理解歌词。曲式工作标签和低置信度句时刻仍待人耳确认。

`AnalyserNode` 使用 2048 点，低频 30–250 Hz、高频 2–10 kHz。沿用 Web 分析归一化与 30ms 起 / 180ms 落；运动导演的能量包络改为 25ms 起 / 150ms 落，移除原来的多重慢平滑。音频关闭时，保留 0.18 的基础流速和原有章节/句时间，移除音频波前与声学加速。

Unity 的 `timeline.json`、`beats68.json`、`parameter-contract.json` 和全部 52 个参数名继续保留，四锚点 82 个标量分量精确等于预设。**不宣称 52 个参数全部拥有独立 Web 材质实现。** 当前直接参与新运动的是光心、贝塞尔方向、花形成/释放、黑隙、雾透明度、两光增益和雨参数；散景、原图景深与部分细节仍随采样外观保留。Web 开场渐显由 8 秒缩短为 1.2 秒，使第一秒已有完整主体；这项 Web 演示调整未写回 Unity。

## 锚点如何经过

令 Δ 为距最近锚点的带符号时间，构图自由度为 `1 − exp(−Δ² / 2.8²)`。输出位置在持续运输状态与“精确目标 + 当前速度 × Δ × 0.72”之间平滑约束。Δ=0 时正好重建目标；此时仍保留穿过目标的速度，不清空 GPU 状态，不在前后安排静止帧。附加雨、亮度调制和雾柔化也平滑收敛，避免破坏关键构图。

暂停保留当前状态；拖动或重新播放会明确重建模拟。因此，任意跳到非锚点时刻的画面，不保证与从头连续播放逐像素相同。四个精确锚点可独立复现。参考叠图只在 O 开启时作为独立 HTML 图像显示，所有测量截图都关闭了它。

## 代码和复现入口

| 文件 | 用途 |
|---|---|
| `src/shape-renderer.mjs` | GPU 双缓冲状态、材料细节重建、雾/细丝合成、雨 |
| `src/flow-field.mjs` | 在当前位置求值的输运场、两光旋涡、传播波前、花和黑隙约束 |
| `src/motion.mjs` | 曲式速度、实时 onset/节拍事件、时间积分和锚点约束 |
| `src/score.mjs` / `src/audio.mjs` | 同源合同求值 / 音频时钟与实时测量 |
| `tools/build-correspondence.py` | 重新生成精确双射和连续运输缓存，验证每个像素覆盖一次 |
| `data/performance-features.json` | 完整实播采集后重采样到 20Hz 的四个标量，用于离线视频；不是音频 |
| `tools/capture-flow-evidence.mjs` | 顺序录制同段、音频关、主歌、主体和锚点经过 |
| `tools/compose-flow-evidence.py` | 生成并排视频、无声 GIF、两秒对比和编码检查 |

```sh
npm test
node tools/verify.mjs
node tools/full-song.mjs
node tools/capture-flow-evidence.mjs
node tools/render-backup.mjs
```

测试工具使用已安装的 Playwright，可设 `PLAYWRIGHT_PATH`、`CHROME_PATH`；Python 预处理需要 Pillow、NumPy、SciPy，录像合成需要 FFmpeg。普通演示不需要这些工具。`flow-proof.mjs` 支持 `PROOF_LABEL / START / DURATION / AUDIO / POINTS / BASELINE`；实际变量以 `PROOF_` 为前缀，如 `PROOF_START`。编码器预热三秒后裁切，避免实录开头黑屏和音画起点偏移。

离线备份以固定步长调用同一个 GPU 渲染器，使用完整实播采集的四个声学标量，再合成本地原曲。交互演出使用即时测量，视频使用缓存，细部轨迹不宣称逐帧相同。所有音频、含音频视频、编码中间文件与浏览器配置保存在 Git 忽略的 `LocalOnly/`。
