# 《晴天》Web 实时粒子演出

当前保留图像采样版。2026-11-16 按用户要求删除程序生成试验版，主入口恢复为 `src/shape-renderer.mjs`；原曲、参考图、图像版验收录像及整曲备份保留。

WebGL2 + Web Audio + 本地 Node 静态服务。没有运行时 npm 依赖、CDN、网络字体或在线接口。只使用 WebDemo，不启动或修改 Unity。

## 演示入口

1. 双击 **启动演示.cmd**，等待“本地音频已就绪”，点击“播放整首晴天”。本机已装 Node 与 Chrome。
2. 按 **F 全屏、H 隐藏界面**。全曲 269.747 秒，前后渐隐；不要直接双击 HTML。
3. 按 D 打开参数面板，切换“形体音频驱动”。推荐在副歌 105–115 秒看开关差异；P 关闭小亮点，检查主体是否仍在运动。
4. 五项证据集中在 [验收页面](http://127.0.0.1:47841/review.html)，可同步播放两段视频。
5. 现场备用文件：**LocalOnly/晴天_整曲备份.mp4**，双击即可播放，不依赖网页或网络。

输入框获得焦点时，除 Esc 外不接管快捷键。点击画面后恢复。画质档位为 1672、1280、960 像素宽，始终等比适配；演示建议接电。

## 这次重做的主体

**画面由独立 GPU 粒子构成，参考图提供初始位置和颜色属性。没有把整张图作为背景，也没有用整幅纹理网格扭动作为最终渲染。**仅开启 O 时叠加单独的参考图元素。

主光体在原画质有 1,573,352 个密集微粒，用浮点高斯叠加形成连续的雾、花和光带。各粒子有独立深度和连续滑移；宏观运动由共同的大尺度流场组织，包含两光区域的不同旋转、反向漂移、伸展、向外冲击与向上涌起。程序光纤读取合同中的贝塞尔路径，并随同一个场运动。细小星尘只作为附属层，最多 12,000 槽。

亚像素高斯核以真实浮点中心计算覆盖，避免硬点跨像素的跳格。画面外缘逐渐消散，避免流动后露出矩形切边。深度分布与透视投影提供前后不同的横移和推进；这是 **2.5D 参考引导重建**，不是从静态图恢复真实三维体积，也不是 Navier–Stokes 流体模拟。该密集重建预算不能当作手机 VFX 的星尘数量预算。

P 模式取消额外小亮点的绘制，并改用结构色彩属性：对源图做 σ=2.8px 高斯低通，以抑制其中细小亮点。它仍由大量微粒组成大形体；光带和雨保留。低通不会抹去所有原始纹理，但动态不依赖额外亮点、随机闪烁或短寿命发射。

## 音乐实际驱动什么

| 时间尺度 / 信号 | 当前实际渲染作用 |
|---|---|
| 四章与四锚点 | 同源合同与目标属性五次平滑过渡，保留两光关系、颜色、黑隙与构图 |
| 曲式工作标签 | 主歌运动等级 0.58，副歌 1 为 1.50、副歌 2 为 1.70；段落边界用 2.4 秒渐变 |
| 歌词句包络 | 花区域伸缩，合同的两光尺度、花形成度、星尘目标数继续求值 |
| 实时 RMS / 低频 / 高频 | 加权能量进入宏观位移幅度和相位速度；能量有 55ms 起、320ms 落，再经 180ms 平滑；不是把音量直接当位置 |
| beats68 既定节拍 × 实时能量 | 全局向外和向上的冲击，26ms 起势、430ms 释放；镜头也受到小幅冲击 |
| 低频 / 高频的原合同映射 | `FiberWidth`、`RainSpeed`、`NoiseAmp` 落到程序丝带与雨的宽度、速度和弯曲扰动 |

章节、歌词句与曲式来自时间标注；**音量与频段实时测量，节拍时刻使用既有 beats68，不宣称在线检测 BPM**。曲式采用 timeline-source 的已有工作标签，仍标注“待人耳确认”，没有把四个视觉章当成主歌副歌。

`score.mjs` 保留 Unity ScoreModel 的时间语义与全部 52 个参数名、82 个标量分量。所有参数仍按同一合同计算；但不是每个值都有独立 Web 材质旋钮，例如 MistSize、原有散景和细部景深仍在参考采样外观中，不应把“JSON 有参数”说成“全部独立实现”。宏观运动的派生量列于面板：段落等级、整体幅度、实时能量、惯性冲击、镜头推进、锚点穿行相位。

音频由 `AnalyserNode` 2048 点读取，30–250Hz 低频、2–10kHz 高频，基础分析 30ms 起 / 180ms 落。当前固定归一化是艺术初值，不冒充整曲 p97 校准。Web Audio 与 Unity FFT 标度不同，不保证逐点相等。音乐响应强度默认 **1×**，调整范围 0.25–2；动态幅度 0–1.8。关闭音频驱动仍播放歌曲，取消声音的形体调制，只保留微弱基础流动。

## 锚点是经过，不是停靠

已移除旧版“锚点前后六秒回到原位”的自由度窗。当前用经过四锚点的连续轨迹：基准路径减去锚点插值修正，加上带符号的穿行函数。精确锚点偏移为零，但路径斜率通常非零，因此前后继续穿行，不在该处减速停住。原合同 0.85 秒参数约束窗口不变。

跳到某一秒会重新初始化运动相位；连续播放的相位由此前实时能量积分。所以随意拖动后，非锚点画面不保证与从头播放逐像素相同，四个精确锚点仍可比较。这是有历史的音频运动，不是预录视频。

## 本地音源与隐私边界

本机同源音频放在 `LocalOnly/QingTian.wav`，48kHz 双声道、269.747208 秒；开始前完整解码。新克隆不含歌曲，可在页面本地选择或恢复该路径。没有文件上传接口，长度相差超过 1 秒会提示选择同版本歌曲。

`LocalOnly/` 整体被忽略，常见音视频扩展名也被忽略。含原曲的所有验收录像、整曲备份和编码中间文件只在此目录。完整歌词没有复制到 Web 数据。服务只监听 127.0.0.1:47841；启动器复用已运行的同一服务，离线可用。

## 文件、证据和复现

| 文件 | 用途 |
|---|---|
| `src/shape-renderer.mjs` | 独立密集微粒、连续高斯覆盖、程序光带、雨、可关的小亮点 |
| `src/motion.mjs` | 大尺度流场、形体运动导演、节拍惯性、纵深投影、锚点穿行 |
| `src/score.mjs` / `src/audio.mjs` | 同源参数求值 / 音频时钟与实时分析 |
| `data/` / `references/` | 同源输入、曲式安全子集、结构色彩缓存；输入 SHA 在 source-manifest |
| `review.html` | 五项验收集中入口 |
| `风格帧对比报告.md` | 四锚点指标、四段实录、完整播放与性能结果 |
| `动态参考调研.md` | YouTube / TouchDesigner 来源，区分实看与字幕依据 |

验证：`npm test`；服务开启后 `node tools/verify.mjs`、`node tools/macro-proof.mjs`、`node tools/full-song.mjs`。工具使用本地 Playwright，可设 `PLAYWRIGHT_PATH`、`CHROME_PATH`。测量脚本 `tools/compare.py` 与 `tools/measure-motion.py` 需要 Pillow、NumPy、SciPy、FFmpeg。普通演示只需 Node、Chrome。

备份导出：`node tools/render-backup.mjs`。1600×900 / 60fps，WebCodecs 固定步长调用同一渲染器，再由 FFmpeg 合成本地原曲。离线使用既有音频特征缓存，交互版使用实时分析；细部动态不宣称逐帧相同。可设 `RENDER_START`、`RENDER_DURATION`、`RENDER_FPS` 作短片检查。

技术依据：[Web Audio 时域采样](https://developer.mozilla.org/en-US/docs/Web/API/AnalyserNode/getFloatTimeDomainData)、[WebGL 实践](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)、[WebCodecs VideoEncoder](https://developer.mozilla.org/en-US/docs/Web/API/VideoEncoder)。
