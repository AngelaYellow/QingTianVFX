# Unity / VFX Graph 来源核查（方案1.2附件）

查阅日期：2026-11-15；路线修订与iPhone构建条件核查：2026-11-16。本文保留来源证据，不记录实时工程进度；“建议”是本项目判断，不是官方性能保证。

当前范围：独立QingTianVFX，先Windows Unity编辑器与M1无粒子参数演出；暗幕、纯黑背景、30fps、68 BPM和四个精确参数锚点已确定，M2以后才做粒子。未来iPhone（Metal/ARKit）、AR和手套后置，手套本轮不做接口。[DEVELOPMENT.md](../../../DEVELOPMENT.md)是唯一开发上下文与最高工程文档；本文不是另一份实施状态记录。

## 1. 版本、平台与真正的风险边界

- 本机已核实可用编辑器为6000.3.28f1，配套URP/VFX Graph为17.3.0；新工程需独立检查manifest/lock及导入。包随编辑器分发，显示的主次版本不描述所有补丁差异。[Unity 17.3 Requirements](https://docs.unity3d.com/Packages/com.unity.visualeffectgraph@17.3/manual/System-Requirements.html)
- VFX Graph可用于URP/HDRP；URP需Linear，硬件需compute shader与SSBO。官方仍将URP/mobile列为未结束preview。当前先在Windows编辑器验收，未来iPhone的Metal与具体图效果另外真机核验，不能由编辑器通过推断设备支持。[官方要求](https://docs.unity3d.com/Packages/com.unity.visualeffectgraph@17.3/manual/System-Requirements.html)
- 不存在本效果通用的手机粒子数量保证。屏幕覆盖、透明叠层、顶点数、采样、分辨率、排序与散热都改变预算。容量/活粒子/strip顶点应分别统计；官方“millions”只是GPU方案规模描述，不是本项目帧率指标。[Unity 粒子系统对比](https://docs.unity.com/en-us/engine/6000.3/manual/visual-effects/particle-systems/choosing-your-particle-system)

## 2. VFX Graph、内置粒子和 Three.js

| 方案 | 可核实事实 | 对本项目的判断 |
|---|---|---|
| VFX Graph | GPU模拟、节点图、C#通过暴露属性与事件控制；不以C#逐个读写粒子为常规接口 | 大量星尘、连续丝带和形态目标很合适；用户可搭图、助手提供HLSL，但GPU平台门槛需最早验证 |
| 内置 Particle System | C#可完整访问粒子，模块化搭建，并能结合Jobs；支持管线更广 | 简单尘点/雨/雾能实现；复杂曲线、四状态连续成形仍需更多自定义；不满足用户指定“必须VFX Graph”的实施约束 |
| Three.js | `Points`支持点云；`AudioAnalyser`提供频谱；`WebGPURenderer`可选WebGPU并回退WebGL2 | 能制作相近视觉并用于网页验证；粒子模拟、工具与原生AR/设备工作流需另组织；本任务选Unity是工作流契合 |

来源：[Unity 对比](https://docs.unity.com/en-us/engine/6000.3/manual/visual-effects/particle-systems/choosing-your-particle-system)、[Three Points](https://threejs.org/docs/pages/Points.html)、[AudioAnalyser](https://threejs.org/docs/pages/AudioAnalyser.html)、[WebGPURenderer](https://threejs.org/docs/pages/WebGPURenderer.html)。WebGL回退不能被解读为所有WebGPU compute功能自动等价可用。

## 3. 视觉层实现依据

建议：雾用少量半透明软边Quad/翻页贴图，光斑用少量较大Quad，星尘用小Quad，斜雨用定向拉长Quad；花形用同一粒子ID对应参数曲面/点集目标；丝带用Particle Strip。黑隙是粒子避让/透明度衰减区域；暗幕是另一个已确定的背景方案，二者不混用。这些是M2后方案，静态图不能唯一反解原始实现。

- 本地17.3官方文档 `Documentation~/Context-OutputStripQuad.md` 明确 Output ParticleStrip Quad 将条带输出为连续Quad带，有 Unlit、HDRP Lit、URP Lit 形式。URP的光纤建议先Unlit，以减轻灯光计算。远处“烟雾”不要误用HDRP专属 Volumetric Fog 输出。在线条带页本次访问失败，本地随包文档已读取，不能谎称网页读取成功。
- 混合选项包括 Alpha、Premultiplied Alpha、Additive。透明默认不写深度；Alpha/Premultiplied默认会启用排序，排序本身耗资源；Soft Particle解决与几何相交硬边，不等于景深虚化。[VFX 输出设置](https://docs.unity3d.com/Packages/com.unity.visualeffectgraph@17.3/manual/Context-OutputSharedSettings.html)
- 因透明深度问题，建议第一轮用“细锐星尘 + 软边大光斑 + 预模糊雾贴图”建立虚实，不假设开一个DOF就能自动让所有透明粒子按自身深度正确虚化。真正DOF是后续单独验证项。

## 4. Custom HLSL 的准确边界

- Custom HLSL Block 可读写粒子属性，适用 Init、Update、Output；函数返回 `void`，需要一个 `inout VFXAttributes`。适合目标位置、吸附力、噪声偏移、黑隙衰减、寿命内颜色与大小计算。[Block](https://docs.unity.cn/Packages/com.unity.visualeffectgraph@17.3/manual/Block-CustomHLSL.html)
- Operator 是输入输出计算，不能接 `VFXAttributes`，最多4个函数参数。复杂公式可拆函数或打包float向量，不要承诺把几十个独立参数直接接入一个Operator。[Operator](https://docs.unity.cn/Packages/com.unity.visualeffectgraph@17.3/manual/Operator-CustomHLSL.html)
- 外部 `.hlsl` 能复用辅助函数；这些节点在compute/vertex上下文工作，`ddx/ddy`不可用，纹理采样需显式mip。它不是替代Output材质/片元Shader Graph的整套渲染器。共享Block跨不同粒子属性布局可能要条件编译。[通用约束](https://docs.unity3d.com/Packages/com.unity.visualeffectgraph@17.3/manual/CustomHLSL-Common.html)
- C#负责音频时钟、数据读取、插值/包络、归一化、暴露参数与事件；GPU负责每个粒子的位置和渲染。可用HasFloat等检查合同、缓存Property ID，固定seed辅助截图复现。切换visualEffectAsset会重置部分状态，连续演出宜保留图而持续驱动。[VisualEffect API](https://docs.unity.cn/Packages/com.unity.visualeffectgraph@17.3/manual/ComponentAPI.html)

## 6. 音频：时钟、特征与节拍需分工

- `AudioSettings.dspTime`基于音频处理采样数，精度高于`Time.time`，适合作为音乐主时钟基础；暂停/seek/恢复仍需脚手架定义状态和偏移。[dspTime](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/AudioSettings-dspTime.html)
- `GetSpectrumData(float[],...)`使用输出采样率，数组必须是64–8192的2次幂；复用数组避免逐帧分配。官方特别提醒这是短历史窗口，第一次调用需要积累数据，不适合严格时序或低延迟关键分析。因此它适合本项目亮度/扰动调制，不能直接宣称是可靠节拍识别器。[GetSpectrumData](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/AudioSource.GetSpectrumData.html)
- 本项目已选68 BPM：从既有约136 BPM时间列隔拍采样，比较两相位并记录局部声学依据，再提供本地核对音频供复听；不把选中相位等同小节第一拍。歌词与章节仍来自时间线，FFT不理解歌词。
- M1采用平滑锚点权重：章节基态经过四预设，句/快层偏移在56.80/93.61/155.41/264.05秒归零，最终视觉参数精确等于预设；原始RMS等信号保留。它是本项目设计约束，不是Unity现成功能，也不是像素级复刻证明。

## 8. 性能与未来iPhone / AR条件

- 透明覆盖是关键：先压雾的屏幕面积和叠层，再压星尘数；选择Unlit、小贴图、低采样，避免全屏多层柔光反复覆盖。降低渲染分辨率能帮助判断是否受fill rate限制。[Unity透明overdraw解释](https://docs.unity3d.com/cn/2020.3/Manual/OptimizingGraphicsPerformance.html)
- URP建议按需关闭Opaque/Depth Texture、额外灯光、阴影等，并以Profiler/Frame Debugger测量；有Soft Particle/深度功能时不能盲关Depth。HDR若为了Bloom保留也要计入带宽。[Unity6.3 URP性能](https://docs.unity3d.com/6000.3/Documentation/Manual/urp/configure-for-better-performance.html)
- 官方移动后处理建议包括关闭High Quality Filtering的Bloom；低端用Gaussian DOF而非Bokeh DOF。项目建议先禁DOF、只试轻量Bloom，用粒子素材自身虚实还原，确认有余量才增加后处理。[Unity6.3 移动后处理](https://docs.unity.com/en-us/engine/6000.3/manual/post-processing-and-full-screen-effects/urp/integration-with-post-processing)
- Unity的iOS构建有两个阶段：生成Xcode工程，再由Xcode生成应用；本地构建应用需要macOS，因为Xcode仅在macOS运行。当前Windows编辑器验收不等于已具备iPhone本地构建环境。[Unity6.3 iOS构建](https://docs.unity3d.com/6000.3/Documentation/Manual/iphone-BuildProcess.html)
- Unity6.3兼容页列iOS15及以上、推荐Xcode16及以上；Metal支持iOS Player与URP。ARKit自身的更早平台基线不能取代Unity6.3完整构建要求，Windows编辑器也不能替代Metal真机核验。[iOS要求](https://docs.unity3d.com/6000.3/Documentation/Manual/ios-requirements-and-compatibility.html)、[Metal兼容性](https://docs.unity3d.com/6000.3/Documentation/Manual/metal-requirements-and-compatibility.html)
- 未来ARKit阶段需iOS模块、启用Apple ARKit XR Plugin、填写相机用途说明并通过Project Validation；选择匹配的AR Foundation/ARKit版本后再核验具体iPhone、系统与功能支持。本轮不安装、不签名、不构建。[ARKit6.3配置](https://docs.unity3d.com/Packages/com.unity.xr.arkit@6.3/manual/project-configuration-arkit.html)
- ARCameraBackground显示摄像机图像，Additive不能将现实变黑。当前已选暗幕纯黑方案；未来AR用明确的暗幕区域承载画面，黑隙继续作为粒子留白，合成效果到AR阶段单独验证。[AR相机组件](https://docs.unity3d.com/Packages/com.unity.xr.arfoundation@6.3/manual/features/camera/camera-components.html)
- M2以后先在Windows编辑器完整播放并测帧时；30fps是当前目标，M1无粒子性能不证明后续视觉预算可行。未来iPhone Metal另测GPU/CPU、内存、长时运行与恢复行为，手机及手套不作为本轮M1前置条件。

## 9. 不确定项清单

1. 未来iPhone型号、系统、macOS/Xcode环境与ARKit实际功能尚待后续确认；不阻挡当前Windows M1。
2. 粒子预算与透明覆盖上限属于拟议值，不可写成性能实测。
3. 暗幕形式已确定，但未来AR中的尺寸、锚定与合成仍需视觉验证；Additive不能独立生成遮黑效果。
4. 官方/社区MCP公开文档持续更新，已装版本与工具发现结果才是实施时依据。
5. 原图实际运动、生成方式、深度、粒子数无法唯一反推，需明确标“推测”。
