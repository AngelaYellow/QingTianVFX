# 给审阅者：这次 Web 主体流动重做

这是图像采样路线的迭代；源图片继续参与颜色与锚点目标。目标是让组成粉雾、青雾、光丝和花的材料持续输运，在四个时刻经过原构图，并让音乐推动推进、卷曲、释放和亮度。Unity 工程不在本次实现范围内。

## 改在哪里

| 改前问题 | 现在的处理 | 从哪里读 |
|---|---|---|
| 每帧从固定采样 UV 加位移，没有粒子历史 | GPU 双缓冲保存位置、速度、年龄、深度，按当前位置求速度并积分 | `src/shape-renderer.mjs` 的 simulationFragment、simulate |
| 相邻纹理被打散、主体像一张薄布 | 雾与细丝使用不同年龄组织；雾持续补入并单独柔化，细丝保留成束纹理 | 同文件 bodyVertex、bodyFragment、resolveFragment |
| 四图同 UV 颜色交叉淡化 | 每个材料 ID 有四份目标坐标；空间分区对应、连续运输坐标、目标几何迁移 | `tools/build-correspondence.py`、`data/correspondence/` |
| 声音只调几个混合系数，反应慢 | 低频/RMS 推进，高频细卷，实时 onset 与节拍分别发射传播波前，快速起势后释放 | `src/motion.mjs`、`src/flow-field.mjs` |
| 锚点附近把运动一起压零 | 约束位置经过目标，保留当前速度；模拟不清空，原采样只在精确时刻完整重建 | `anchorState` 与 bodyVertex 的锚点约束 |
| 157 万状态全量模拟不稳 | 262,144 个 GPU 材料状态与 1,573,352 个锚点细节采样分离；渲染之间作速度预测 | `shape-renderer.mjs` 的状态纹理、carrier/detail 逻辑 |
| 雨变速会因绝对时间乘速度而倒跳 | 按秒积分雨的路程 | `motion.mjs` 的 rainPhase |

JS 负责 AudioContext 时钟、音频测量、时间线与全局信号；没有运行时逐粒子 CPU 更新循环。几何和颜色都依赖被授权的采样素材，不应将本结果称作无参考程序生成或真实三维流体。

## 审阅重点

1. 主体是否有足够的推进、拖曳、翻卷和消散，任意中间帧是否仍完整；是否还有“只动细点”的观感。
2. 低频推动与 onset 波前是否看得见，强弱是否合适；主歌和副歌速度、展开程度是否有明确差别。
3. 锚点前后是否有停靠、吸回或突然变清晰的观感。精确截图相似不能单独证明过渡自然。
4. 雾与细丝比例是否合适：中段过糊、过散、细丝被雾覆盖等审美问题，要结合实录判断。

本次工程验证与截图测量不代表用户已经接受动作质感。下一轮以用户和审阅者的实际画面反馈调整，不把当前系数直接冻结到 Unity。
